## 2. Gemini Usage Audit

* **Which itinerary sections are Gemini-generated?**
  * Itinerary metadata (Destination name, total days, budget, comfort level, transport preference).
  * Day-wise structured regional segments (Regions name, regional coordinates, quick summary, local transport type, hotel types, estimated cost, list of places, food recommendations, and timeline activities).
* **Which sections are still hardcoded?**
  * Destination base city panels and details (base city name, hotel recommendations, food recommendations, and connectivity notes) are hardcoded with preset destination mappings (e.g. Meghalaya maps to Shillong, Kerala to Kochi, Rajasthan to Jaipur).
  * Travel tips and packing guidelines in the Blueprint panel are hardcoded static recommendations.
* **Which sections still use fallback templates?**
  * If the Gemini request fails, a local mock itinerary template is loaded.
  * If selected places in the cart are empty, the Blueprint page uses fallback attraction cards.
* **Which sections are mock data?**
  * Transport options and exact budget breakdown percentages are calculated and formatted client-side or post-processed by backend helper methods rather than being directly generated by Gemini.
  * Travel tips, weather, packing lists, and safety suggestions in the Blueprint are currently mock data.

## 3. Blueprint Audit

* **How Blueprint map is currently generated:**
  * It uses preset coordinate offsets (`presetCoords` in `posterBuilder.js`) to plot nodes on an SVG canvas to resemble an artistic poster rather than an interactive Leaflet/GPS map.
* **Whether Gemini contributes to Blueprint generation:**
  * NO. The Blueprint is generated client-side from the active trip data (regions, selected attractions) using local layout and styling logic.
* **Whether Blueprint is static:**
  * Mostly static. The itinerary schedule, regions list, and coordinate lines are dynamic (extracted from the trip plan), but the base city recommendations, packing list, weather details, and travel tips are static or choose from limited predefined templates.
* **Whether Blueprint is AI-generated:**

## 4. Performance Audit

* **Time to generate itinerary:** ~25 - 30 seconds. (Fallback pipeline queries Nominatim, crawls for Unsplash images, runs Gemini prompt, validates coordinates, and requests OSRM routes).
* **Time to load attractions:** ~2.5 seconds (concurrent Nominatim calls).
* **Time to load images:** ~300ms (uncached) / ~10ms (cached from `image_cache.json`).
* **Time to generate blueprint:** ~15ms (instant client-side SVG generation).
* **Time to generate budget:** ~100ms (client-side calculation / `/api/budget-breakdown` request).

**Slowest Component:** Gemini API generation combined with sequential API validation logic in the backend.
